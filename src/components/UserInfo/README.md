# کامپوننت‌های اطلاعات کاربر

`UserInfoNumber` و `UserInfoString` کامپوننت‌های کوچک و قابل‌استفاده مجدد برای نمایش اطلاعات پروفایل کاربر هستند.

اصل طراحی این دو کامپوننت این است که فقط مسئول **نمایش** باشند. بنابراین دریافت داده از API، تغییر داده، mutation و مدیریت state باید در لایه صفحه یا feature انجام شود. این تفکیک باعث می‌شود کامپوننت‌ها ساده، قابل تست و قابل استفاده در چند بخش مختلف باشند.

## `UserInfoNumber`

### کاربرد

برای نمایش آمار عددی پروفایل مانند تعداد پست‌ها، دنبال‌کننده‌ها و دنبال‌شونده‌ها استفاده می‌شود.

```tsx
import { UserInfoNumber } from "@/components/user-info";

<UserInfoNumber label="دنبال‌کننده‌ها" value={1280} compact />
```

### Props

- `label: string` — برچسبی که زیر مقدار نمایش داده می‌شود.
- `value: number` — مقدار عددی که از API یا state دریافت می‌شود.
- `compact?: boolean` — در صورت فعال بودن، اعداد بزرگ به شکل فشرده و متناسب با locale نمایش داده می‌شوند.
- ویژگی‌های استاندارد `HTMLDivElement` مانند `className` نیز قابل استفاده هستند.

### دلیل وجود تابع کامپوننت

تابع `UserInfoNumber` داده ورودی را به متن قابل نمایش تبدیل کرده و رابط کاربری مربوط به آن را رندر می‌کند. این تابع عمداً مسئول دریافت داده، ارسال درخواست، mutation یا نگهداری state نیست؛ چون این مسئولیت‌ها باید در لایه بالاتر قرار داشته باشند.

### دلیل وجود قالب‌بندی عدد

قالب‌بندی داخل کامپوننت انجام می‌شود تا همه استفاده‌کننده‌ها ظاهر یکسانی داشته باشند و منطق نمایش عدد در صفحات مختلف تکرار نشود. حالت `compact` نیز برای جاهایی است که فضای رابط کاربری محدود است.

## `UserInfoString`

### کاربرد

برای نمایش اطلاعات متنی کوتاه کاربر مانند موقعیت مکانی، نقش، نام کاربری یا سایر اطلاعات متادیتای پروفایل استفاده می‌شود.

```tsx
import { UserInfoString } from "@/components/user-info";

<UserInfoString label="موقعیت" value="Reading, UK" />
```

### Props

- `label: string` — برچسبی که زیر مقدار نمایش داده می‌شود.
- `value: string` — مقدار متنی دریافت‌شده از API یا state.
- `fallback?: string` — متنی که در صورت خالی بودن `value` نمایش داده می‌شود و مقدار پیش‌فرض آن `—` است.
- ویژگی‌های استاندارد `HTMLDivElement` مانند `className` نیز قابل استفاده هستند.

### دلیل وجود تابع کامپوننت

تابع `UserInfoString` مقدار متنی را برای نمایش نرمال می‌کند و رابط کاربری را رندر می‌کند. دریافت یا ویرایش اطلاعات پروفایل در این تابع انجام نمی‌شود تا کامپوننت یک مسئولیت مشخص و قابل استفاده مجدد داشته باشد.

### دلیل بررسی مقدار خالی

با حذف فاصله‌های ابتدا و انتهای رشته، مقدارهایی که فقط شامل فاصله هستند نیز خالی تشخیص داده می‌شوند. در چنین حالتی `fallback` نمایش داده می‌شود تا رابط کاربری به جای یک فضای خالی، وضعیت مشخص و قابل فهمی داشته باشد.

## الگوی پیشنهادی استفاده

```tsx
<div className="flex gap-6">
  <UserInfoNumber label="پست‌ها" value={42} />
  <UserInfoNumber label="دنبال‌کننده‌ها" value={1280} compact />
  <UserInfoString label="موقعیت" value="Reading, UK" />
</div>
```

داده‌ها باید در صفحه یا feature دریافت شوند و سپس به این کامپوننت‌ها از طریق props داده شوند. به این ترتیب UI از منبع داده مستقل می‌ماند.


## مستندات JSDoc

برای هر دو کامپوننت، مستندات JSDoc مستقیماً بالای تعریف کامپوننت قرار گرفته است. این مستندات شامل موارد زیر هستند:

- توضیح مسئولیت و هدف کامپوننت
- توضیح هر ورودی مهم با `@param`
- توضیح خروجی با `@returns`
- مثال استفاده با `@example`
- توضیح دلیل قرار گرفتن منطق قالب‌بندی یا مدیریت مقدار خالی در کامپوننت

این JSDocها باعث می‌شوند توضیحات کامپوننت هنگام استفاده در محیط‌هایی مانند VS Code نیز قابل مشاهده باشند و نیاز به مراجعه مداوم به فایل README کاهش پیدا کند.
